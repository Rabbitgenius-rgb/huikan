# 暂存适配：Codex

当前主线专注 DeepSeek Harness，Codex 默认关闭。此目录及 `desktop/codex-setup.cjs` 保留供后续独立维护。默认设置页不显示 Codex，主进程不注册安装接口，浮窗不注册 Codex 心跳/上下文，也不接受新的 Codex 保存；默认安装包不包含 MCP 服务。

开发者确需回归时，运行 `npm run test:codex`。显式设置 `HUIKAN_ENABLE_CODEX=1` 后构建，才会打包暂存适配；这不会自动修改任何全局配置。已有 Codex 摘录、来源校验与去重兼容保留，不迁移或删除资料。

# Huikan Codex 本机适配

需要回看 0.3.0 或更新版本。这个插件通过本机 STDIO MCP 把用户明确指定的原文保存到回看工作台，读取某个 Codex 线程的既有摘录，并切换浮窗到该线程。它不会扫描 Codex 会话文件、读取账号密钥或自动采集整段聊天。

在仓库根目录运行 `node codex-plugin/scripts/build.mjs` 后，`dist/server.cjs` 是包含本机通信依赖的独立入口。使用源码插件需要 Node.js 22；桌面安装包的设置可注册内置运行环境，无需额外安装 Node。

Codex 的 MCP 配置支持本地 STDIO command/args。配置后需要重启连接；安装了配置不等于已经验证连接。插件清单使用 portable `plugin.json`、`mcp.json` 和 `skills/`；本目录没有需要用户信任的生命周期 hook。

每次与线程相关的调用都需要明确的技术 `threadId`，归属标记为 `caller-supplied`。当前执行环境的 `CODEX_THREAD_ID` 可作为兼容入口，但并非官方保证的稳定公开接口；不存在时需由用户提供线程链接，不回退到根 session 或最近聊天。`show_recalls` 只在明确调用后切换，不能保证随前台标签页自动切换。回跳只打开 Codex 线程，不定位具体消息。

保存只在 `status: "saved"` 时完成。遇到 `pending`/超时应保留原文并复用 `requestId` 重试；相同内容全局去重会保留首次保存的来源。

## 历史接入步骤（仅适用于显式启用的构建）


0.3.0 起，桌面版内置本机 MCP 服务，无需额外安装 Node.js 或配置 OpenAI API Key。

1. 退出旧版回看，打开 0.3.0 或更新版本；保持“启动时自动连接”开启，进入 **连接与识别设置 → 连接 Codex**，点击 **连接 Codex**。
2. 在 Codex 的 MCP 设置中重新加载连接，或重新打开 Codex。回看收到实际 MCP 握手后才显示“已连接”。
3. 在 Codex 聊天中说“把这段留作回看”，明确要保存的原文；也可以指定主题。需要查看已存内容时，说“打开这场对话的回看”。

配置只添加回看自己的 MCP 项，其他服务器和已有设置保留；遇到未知的同名配置会停止，不覆盖它。回看应用移动位置后，可在设置中重新配置路径。

来源需要当前聊天的技术 thread ID，由调用方明确提供。当前 Codex 执行环境中的 `CODEX_THREAD_ID` 可作兼容入口，但不是官方保证的稳定接口；缺失时需提供当前聊天的 `codex://threads/...` 链接，不会通过标题、最近聊天或读取会话文件猜测。浮窗在明确调用回看工具后切换，不随前台标签页自动切换。回跳打开原聊天，尚不定位具体消息或选区。

原文保存、自定主题、读取和浮窗切换均在本机完成。不同来源保存相同正文时仍沿用首次保存的条目和来源，工具会报告重复。开发者可使用仓库的 [Codex 插件包](codex-plugin/README.md)。
